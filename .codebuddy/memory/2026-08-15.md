## 环境变量机制（重要结论）

- **TOML 配置不支持 `${ENV_VAR}` 插值**。原 `password = "${NACOS_PASSWORD}"` 会被当作字面字符串，不会读环境变量。
- 真正支持的环境变量是代码 `std::env::var` 显式读取：`CONFIG_PATH`(选配置)、`GRPC_PORT`(gRPC 端口)、`APP_HOME`(锚定相对路径)、`DATABASE_URL`(覆盖 toasty)、`REDIS_URL`(覆盖 sa_token)、`SERVICE_IP`(nacos 注册 IP)。
- 若需 Nacos password 等字段支持环境变量，需扩展 tx_di_nacos 的 bootstrap 读取逻辑（仿 toasty 的 DATABASE_URL 兜底）。

## 配置文件 `${VAR}` 环境变量插值（已实现）

- 用户需求落地：配置文件中的 `${xxx}` 解析为环境变量。方案 = dotenvy 加载 .env + 读文件为字符串 + 替换 `${}` + `toml::from_str`。
- 新增 `tx-di-core/src/config_env.rs`：
  - `ensure_dotenv()`：幂等（OnceLock）加载 .env；路径优先级 `DOTENV_PATH` 环境变量 > CWD 的 `.env`；失败静默。dotenvy 0.15 已在 workspace 声明，tx-di-core 新增 `dotenvy.workspace = true` 依赖。
  - `interpolate_env(input) -> Result<String, String>`：替换 `${VAR}`（未定义报错）与 `${VAR:-default}`（未定义用默认）；其它 `$`（非 `${`）原样保留；未闭合 `${` 报错。手写扫描，未引入 regex。
- 生效路径（两处 TOML 解析入口均加 `ensure_dotenv()` + `interpolate_env()`）：
  - `tx-di-core/src/config.rs::load_config`（`AppAllConfig::new` / `BuildContext::new`）
  - `tx_di_nacos/src/bootstrap.rs::load_local_toml`（`app_loop!` 宏）
  - `BuildContext::with_config`（内存 toml）不经过插值。
- `tx-di-core/src/lib.rs` 导出 `ensure_dotenv` / `interpolate_env`。
- 注意：dotenvy 的 `dotenv()` 返回 `Result<PathBuf,_>`，`from_path()` 返回 `Result<(),_>`，需统一为 `Result<(),_>`。
- 注意：项目里已存在多处 `${VAR}` 占位符（`configs/config_all.toml`、`examples/gb_cams/config`、`examples/gb28181_admin/config`、`tx_di_nacos/examples/app_loop_demo.toml`），之前静默失效，现在会真正解析；未定义且无默认值会报错。可选字段建议用 `${VAR:-}` 空默认值。
- 测试：config_env 6 个单元测试；tx-di-core 集成测试需 `--test-threads=1`（全局状态竞争，见 CODEBUDDY.md）。
