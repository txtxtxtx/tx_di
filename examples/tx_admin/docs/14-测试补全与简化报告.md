## 3. 核心改进：gRPC 测试改为自动化回归（G-2）

### 3.1 问题

`grpc_auth_test.rs` 原先连接固定 `http://127.0.0.1:50051`，依赖开发者在另一终端 `cargo run -p admin_api` 手动启动服务。**不随 `cargo test` 自动通过**，属于"过于复杂的测试"。

### 3.2 改造方式

1. **E2E 基座 `common/mod.rs`**：`TestServer` 结构体新增 `grpc_url` 字段，在启动 App 时记录实际注入的随机 gRPC 端口地址。App 的 `async_run` 本身会启动 gRPC 服务（通过 `GRPC_PORT` 环境变量注入随机端口），故无需额外启动。
2. **`grpc_auth_test.rs`**：改为复用 `common::server()` 基座，从 `srv.grpc_url` 连接客户端，无需任何手动步骤。
3. **新增回归用例**：`test_get_user_info_without_token_rejected` 验证 gRPC 鉴权拦截器对无 token 请求返回 `Unauthenticated`（此前 13 个 service 的拦截行为无自动验证）。

### 3.3 效果

```bash
cargo test -p admin_api --test grpc_auth_test   # 自动通过，无需手动起服务
```

改造后 5 个用例（原 4 个 + 新增鉴权拦截 1 个）全部自动运行。

## 4. 补充 Config/Dict/Log HTTP E2E（G-3）

新增 `admin_api/tests/misc_e2e_test.rs`（7 个用例），补齐此前缺失的 Config/Dict/Log 协议链路（路由 + 鉴权 + JSON 序列化 + 落库回查）：

| 用例 | 覆盖点 |
|------|--------|
| `config_create_and_get_by_key_ok` | 创建配置 + 按 key 回查落库 |
| `config_duplicate_key_rejected` | 重复 key → 业务码 10204（HTTP 200 + 错误业务码） |
| `config_list_paged_filter_by_category` | 分页查询按分类过滤 |
| `dict_create_type_and_data_by_code_ok` | 创建字典类型 + 字典数据 + 按 type 查询 |
| `dict_data_list_filter_by_type` | 字典数据分页按 dictType 过滤 |
| `log_operate_create_and_list_ok` | 创建操作日志 + 列表按 subType 过滤 |
| `config_dict_log_api_requires_auth` | 未登录访问三模块接口均 401（鉴权链路） |

**设计原则**：复用共享 `admin_token()`（进程内仅 1 次登录，规避限流桶）；每用例创建唯一实体（时间戳后缀）可并行可重跑；断言业务码 + 回查持久化（真实行为）。

## 5. 补充 admin_proto DTO 序列化回归（G-6）

`admin_proto/src/lib.rs` 新增内联测试模块（5 个用例），验证共享 DTO 的协议契约，防止 DTO 变更破坏 HTTP/gRPC 双协议：

| 用例 | 覆盖点 |
|------|--------|
| `login_response_u64_serialized_as_string` | u64 字段序列化为字符串（防 JS 精度丢失），含超过 2^53 的大数 |
| `login_response_field_names_camel_case` | 字段名为 camelCase（前端契约） |
| `page_request_accepts_number_or_string` | 反序列化同时接受数字与字符串；序列化恒输出字符串 |
| `create_config_request_roundtrip` | 配置请求序列化往返保持完整 |
| `empty_message_serializes_to_empty_object` | Empty 消息序列化为 `{}` |
