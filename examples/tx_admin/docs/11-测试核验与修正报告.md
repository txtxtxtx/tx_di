### 1.2 不真实测试的根因分析

**假 ID 问题的危害**：`UserAppService::assign_roles` 虽然调用了 `role_repo.find_by_ids(&role_ids)` 校验角色存在，但**没有校验返回数量与输入数量一致**（`roles.len() == role_ids.len()`）。传入不存在的 ID 时，`find_by_ids` 返回空 Vec，for 循环不触发，`bind_roles` 直接绑定悬空引用。测试用假 ID 恰好绕过了这个缺陷，给出虚假的绿灯。

> 这是 `find_by_ids` + `assign_*` 的数据完整性隐患（已记录在 `07-生产就绪评估报告` P0-3 事务问题相关项中），建议后续在 `assign_roles`/`assign_departments` 中增加 `roles.len() == role_ids.len()` 校验。

## 3. 修正前后对比

### 3.1 假测试示例（修正前）

```rust
// delete_operate_logs —— 删除了不存在的 ID=1，什么都没删
app.create_log(...).await.unwrap();
app.delete_logs(&[1]).await.unwrap();  // 日志 ID 是雪花 ID，不是 1
// 无任何断言验证删除效果
```

### 3.2 修正后

```rust
let log = app.create_log(...).await.unwrap();
app.delete_logs(&[log.id]).await.unwrap();  // 用真实雪花 ID
// 验证删除后确实查不到
let page = app.get_log_page(...).await.unwrap();
assert_eq!(page.total, 0);
```

### 3.3 假 ID 绑定示例（修正前）

```rust
// assign_roles_to_user —— 绑定不存在的角色 ID
app.assign_roles(user.id, vec![1, 2, 3]).await.unwrap();  // 角色 1/2/3 不存在
assert!(found.role_ids.contains(&1));  // 悬空引用，测试却绿灯
```

### 3.4 修正后

```rust
let r1 = role_app.create_role(...).await.unwrap();
let r2 = role_app.create_role(...).await.unwrap();
let r3 = role_app.create_role(...).await.unwrap();
user_app.assign_roles(user.id, vec![r1.id, r2.id, r3.id]).await.unwrap();
assert!(found.role_ids.contains(&r1.id));  // 真实角色 ID
```
