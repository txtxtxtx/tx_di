## 一、nacos SDK 选型结论（回答：nacos-sdk-rust 能否用于 tx_di_registry）

> **2026-08-06 更新（D 阶段实施前最终选型）**：**切换到官方 `nacos-sdk` 0.8**。
> 依据（详见 08 文档 §一对比表与 §二风险）：
> - `nacos_rust_client` 的 `register()` 为 fire-and-forget（不检查结果），注册失败静默——服务发现关键路径无声失效
> - 基于 actix 独立线程 runtime，与 tx-di 的 tokio 生态割裂，多客户端/多地址受限，错误处理弱（`unwrap_or_default()`）
> - 官方 `nacos-sdk`：tokio+tonic 原生契合、thiserror 结构化错误、生产功能完整（防推空/磁盘缓存应急启动/鉴权/OTel）、官方组织维护且 CI 测试路径含 rnacos
> - 注意点：tonic 0.14 与项目 admin_proto 的 tonic 0.12 双版本共存（可接受）；写操作服务端不可用时阻塞（配快速失败+后台重试）

### 结论：可以，**推荐用官方 `nacos-sdk`（nacos-group/nacos-sdk-rust）替代 `nacos_rust_client`**

| 维度 | `nacos_rust_client` 0.3.3（当前已依赖） | `nacos-sdk` 0.8.0（官方 nacos-sdk-rust） |
|------|------------------------------------------|--------------------------------------------|
| 维护方 | **heqingpan（r-nacos 作者）** | nacos-group（Nacos 官方组织） |
| 最近发版 | 2026-03-15（0.3.3） | 2026-04-17（0.8.0），近期 0.6/0.7/0.8 连发 |
| 90 天下载 | ~46,510 | ~16,494 |
| 协议 | 1.x HTTP + **2.x gRPC**（`set_use_grpc(true)`） | 2.x gRPC（tonic）+ HTTP（reqwest） |
| 服务注册/心跳 | 支持，`register` 后**自动心跳保活** | 支持 |
| 服务发现/订阅 | `query_instances` / `select_instance` / `subscribe` | 支持 |
| 配置管理 | `set/get/subscribe`（服务端推送） | 支持 |
| 与 r-nacos 兼容 | **同作者，天然配套** | 兼容 2.x 协议，需实测 |
| 接入成本 | **低**：已声明依赖，只补实现 | 高：改依赖、重写两个实现 |
| 技术栈 | actix（后台线程）+ tokio | tonic + tokio，edition 2024 |

**推荐理由**：
1. 当前 `tx_di_registry/Cargo.toml:29` 已声明 `nacos_rust_client = "0.3"`，且 `nacos` feature 已接线（`plugin.rs` 中 `NacosServiceRegistry::new()` / `NacosConfigCenter::new()`），只是方法体是 TODO 占位
2. 与 r-nacos 同作者，服务端-客户端协议验证最充分，且**官方 nacos-sdk 主要针对 Java Nacos 2.x 测试，连 r-nacos 仍需实测**
3. 支持双协议（HTTP + gRPC），可平滑切换；注册后自动心跳，无需自研心跳循环
4. 官方 SDK 的 `nacos-tonic-discover`（gRPC 服务发现适配）若后续需要，nacos_rust_client 同样提供

**决策**：采用 `nacos_rust_client` 0.3.3 补全 `NacosServiceRegistry` / `NacosConfigCenter` 占位实现。若实施中发现 actix 后台线程与 tokio 运行时冲突（概率低），再评估切换 `nacos-sdk`。

### C-1. P0-3 引入事务管理

- **现状**：全库 0 事务；`create_user` 等多步写非原子
- **前置**：toasty 0.8 原生支持 `Db::transaction(&mut self) -> Transaction<'_>`（已核实源码 `toasty-0.8.0/src/db.rs:140`），`Transaction` 实现 `Executor`，支持 `commit/rollback`、嵌套（savepoint）、drop 自动回滚
- **步骤**：
  1. `plugins/tx_di_toasty/src/plugin.rs` 增加：
     ```rust
     impl ToastyPlugin {
         /// 开启事务；需要 &mut Db，内部先 clone Db 再调用
         pub async fn begin_tx(&self) -> RIE<toasty::db::Transaction<'_>> {
             let mut db = self.db().clone();
             db.transaction().await.map_err(...)
         }
     }
     ```
     （注意 `Db::transaction` 签名是 `&mut self`，clone 后持有 `&mut` 期间锁住该句柄；若需并行用 `transaction_builder`）
  2. `tx_di_toasty` 导出 `Transaction`、`TransactionBuilder` 类型
  3. **Repository 层改造**（最小侵入方案）：给关键 repository 方法增加"接受可选项 `tx: Option<&mut Transaction>`"重载成本高；**推荐在 AppService 编排层开事务**：
     - 方案：`admin_app` 新增 `UnitOfWork` 辅助（注入 `ToastyPlugin`），提供 `with_tx(|tx| async { ... })`，内部将 `tx` 传给 repository
     - 但现有 repository 全部自建 `self.plugin.db().clone()`，无法共享 `tx`。**因此需先做注入点改造**：
       a. repository 方法签名统一增加事务入参（改动面大，约 12 个 repo × 每方法）
       b. 或：**折中方案**——仅对"跨表写"的关键用例（`create_user`、`bind_roles`、`bind_departments`、`assign_menus`、`add_users_to_role`、`create_role`、字典批量、Job 变更）先做事务化，单表写暂保持现状
  4. 每处改造后补测试：模拟中途失败（如绑角色时插入失败），断言用户/角色关联已回滚
- **验证**：`real_db_test` 新增"建用户绑角色中途失败 → 用户与关联均不存在"用例通过
