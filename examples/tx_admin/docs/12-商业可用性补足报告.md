# tx_admin 商业可用性补足报告（本批次）

> **日期**: 2026-08-13
> **范围**: 在 `07-生产就绪评估报告` 与 `08-P0-P1实施计划` 之后，针对仍未闭合的
> 「商业可用」缺口进行补足，并修复一个被证实会静默失效的框架级 Bug。
> **验证**: `admin_app` 124 个测试全绿、`admin_api` 健康检查冒烟测试全绿、
> `tx-di-core` 73 个测试全绿，全量编译通过。

---

## 一、核心结论

`tx_admin` 之前「功能完整、可编译、可测试」但「离商业可用仍差一截」。
本批次补齐了**配置化、部署、可观测、数据完整性、会话/数据库多实例**等关键缺口，
并修复了一个会导致 `web_config.layers`（超时/压缩/CORS/安全头）**静默失效**的
DI 框架级 Bug——这是此前评估中「中间件注册了但未生效」的根因。

---

## 二、本批次修复清单

### 🔴 框架级 Bug（影响面最大）

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| F-1 | **配置组件的 `#[component(init)]` 回调从未被调用** | `tx-di-macros/src/codegen/factory.rs` 配置组件工厂路径只做了 `deserialize`，未执行 `inner_init` | 配置组件工厂补齐 `inner_init` 调用 |
| F-2 | **`web_config.layers` 中间件全部静默失效** | F-1 的后果：`WebConfig::init` 里的 `add_layer_by_name` 从不执行 | F-1 修复后 7 个中间件（timeout/security/metrics/api_log/操作日志/compression/cors）真实生效（日志已验证） |

> 修复前启动日志只显示 2 个中间件（手动注册的 metrics/operate_log），
> 修复后显示完整 7 个。这是「配置驱动中间件」首次真正生效。

### 🟠 部署与配置化

| # | 缺口 | 修复 |

| D-2 | 无生产部署文件 | 新增 `examples/tx_admin/Dockerfile`（多阶段：Node 构建前端 + Rust 构建后端 + 精简运行时 + HEALTHCHECK） |

| # | 缺口 | 修复 |

## 五、使用方式

```bash
# 本地开发（SQLite，零依赖）
cargo run -p admin_api

# 生产（PostgreSQL + Redis + Nacos，多实例）
docker compose -f examples/tx_admin/docker-compose.yml up --build --scale tx_admin=3

# 环境变量（均可选，覆盖默认）
CONFIG_PATH=/app/config/config.toml   # 配置文件路径
APP_HOME=/app/data                     # 相对路径锚点（数据/日志/上传）
DATABASE_URL=postgres://...            # 数据库连接串
REDIS_URL=redis://...                  # 会话/分布式锁
ADMIN_INIT_PASSWORD=xxx                # 首次建库管理员密码
SERVICE_IP=10.0.0.1                   # Nacos 注册 IP
GRPC_PORT=50051                       # gRPC 端口
```
