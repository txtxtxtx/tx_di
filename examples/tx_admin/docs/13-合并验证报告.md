## 3. 发现并修复的 Bug

### 3.1 【已修复】Docker 部署 SPA 前端路径错位

**现象**：Docker 容器内访问 `/web` 前端 404。

**根因**：`config.toml` 中 `spa_apps` 使用仓库相对路径：

```toml
[web_config.spa_apps]
"/web" = "examples/tx_admin/web/dist"
```

而 `tx_di_axum` 的 `WebConfig::init` 会对 spa 目录调用 `resolve_data_path`——当 Docker 设置 `APP_HOME=/app/data` 时，该路径被锚定为：

```
/app/data/examples/tx_admin/web/dist
```

但 Dockerfile 原本将前端产物 COPY 到 `/app/web/dist`。`setup_spa_apps` 中 `dist_path.exists()` 检查失败，打印 error 并跳过前端服务。

**修复**（`Dockerfile`）：将前端产物 COPY 目标改为与 `resolve_data_path` 锚定结果一致：

```dockerfile
COPY --from=web-builder /src/web/dist /app/data/examples/tx_admin/web/dist
```

同时为 SQLite 默认库的锚定路径（`/app/data/examples/tx_admin/data/`）补充 mkdir，避免直接 `docker run`（未设置 DATABASE_URL）时 SQLite 父目录缺失。

## 4. 配置建议项（非 Bug，供后续优化）

### 4.1 【建议】production 配置的 SPA 路径与 Docker 锚定语义不一致

`config.production.toml` 中 `spa_apps["/web"] = "examples/tx_admin/web/dist"`。若生产裸机部署时设置 `APP_HOME`，同样会错位。建议：production 部署明确约定 `APP_HOME` 或改用绝对路径。当前 `docker-compose.yml` 使用 `config.toml` 而非 production 配置，因此本次修复已覆盖官方 compose 路径。

### 4.2 【建议】`distributed_lock` 默认关闭

`config.toml` 的 `[job_config]` 未设置 `distributed_lock`（默认 `false`）。生产多实例部署需显式开启（`config.production.toml` 已开启 `true`）。本地单实例不受影响。
